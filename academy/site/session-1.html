1. Session 1 · Where settings live

Architecture

config.py is the boundary between the process environment and the rest of the program. Measure targets, the model switch, and the output folder are read here so triage, the CRM, and the exporters do not each invent their own paths. Secrets are not stored. A missing variable falls back to the deterministic demo, which is what CI runs.

2. Session 1 · Numbers stay in the code

Architecture

The fidelity guard sits between any prose and the reader. Triage, PDSA notes, and steering updates all pass through it. It does not compute rates. It only checks that every number in a sentence already exists in the facts Python produced. That is why a model is allowed to rewrite wording and not allowed to invent a percentage.
