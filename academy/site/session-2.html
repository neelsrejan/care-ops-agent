1. Session 2 · Flatten only what the measures need

Architecture

parse.py is the edge between a FHIR bundle and the relational rows the SQL views expect. It keeps diabetes, hypertension, HbA1c, blood pressure, and mammography codes, and drops the rest of the bundle. Downstream views never see a raw JSON document. That keeps the measure logic in SQL and the file format in one module.

2. Session 2 · Local files into checked tables

Architecture

load.py is the only place that writes the raw tables. It reads local FHIR files and the CMS csv, copies rows into PostgreSQL, then builds the views and runs the SQL tests. CI does not call it, because the raw download is large and gitignored. The unit tests prove the parser and the rate math on fixtures instead.

LOGIC_TRACE.md

Session 2 logic trace — FHIR R4 → PostgreSQL views (2026-11-03)

Snapshot: snapshots/session-2.zip.

  1. Goal. Real public data in tested tables: Synthea patients over FHIR R4 and CMS facility seeds in PostgreSQL, with three HEDIS-style measures as views.
  2. Needed next. S3 needs each measure's denominator roster and partner seeds without recomputing them.
  3. Libraries. psycopg 3 (COPY is fast and safe), PostgreSQL 17 (approved stack; plain SQL views instead of dbt), httpx (downloads, HAPI check). The box runs PG 17 from the official binaries on port 5433 because apt mirrors were failing.
  4. Code. - fhir/parse.py: flattens bundles; keeps diabetes/hypertension conditions, HbA1c, BP panel components (85354-9, or 55284-4 in the 2019 sample; the first load caught this when BP rows were zero), mammography. - fhir/hapi.py: capability check (HTTP 200); upload off by default. - data/download.py: CMS link from the metastore; Synthea CSV + FHIR R4 zips. - data/load.py: schema → COPY → views → SQL tests. - sql/views/*: patient-level rows (who is in the denominator, latest result, met). - metrics/measures.py: counts and Wilson CIs in Python.
  5. Docs. DATA_LICENSES (CMS public domain; Synthea Apache-2.0), data/README with row counts and the baseline check, MEASURES.md, ADR 0003.
  6. Finding. Synthea's HbA1c control is 58 of 58 (values 2.5–7.6%). Screening is 13 of 142. Synthea is used for rosters only, and outcome probabilities come from labeled scenario parameters.
  7. Capability added. python -m care_ops_agent.data.load: 6 SQL tests, all 0 failing rows.
  8. What it proves. FHIR R4 parsing, SQL measure logic, data tests, honest data-quality call.
